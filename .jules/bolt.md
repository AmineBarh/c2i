## 2025-02-20 - Admin Page Data Filtering Performance Optimization
**Learning:** In React functional components with significant UI state (like active tabs, sidebars, Modals), it's a common anti-pattern to compute derived arrays/counts (e.g. `const filteredItems = items.filter(...)`) in the main component body without `useMemo`. This leads to O(N) or O(N*M) recalculations on *every single render*, even when the underlying data (`items`) or filter inputs haven't changed. In `c2i/src/pages/Admin.jsx`, the UI logic (switching between `Dashboard`, `Partners`, etc) was causing continuous recalculations. Furthermore, sequential filtering like `items.filter(cond1).length`, `items.filter(cond2).length` causes multiple full array scans instead of a single `reduce`.
**Action:** When working on components that display dashboards or filtered views of data arrays, always search for un-memoized derived state. Replace sequential `.filter().length` calls with a single `.reduce()` combined with `useMemo` to ensure O(N) complexity overall, isolated from UI re-renders.
