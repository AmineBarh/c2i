## 2024-03-27 - [Memoization Top-Level Page Data Fetch]
**Learning:** Found that multiple top-level category pages in this CRA setup (like `Admin.jsx`, `WebDev.jsx`, `Iot.jsx`, `Automation.jsx`, `Training.jsx`) recalculate derived, expensive loops (`O(N)`) directly in the render body (e.g., `projects.filter(...)`) every time any unrelated state updates. For example, in `Admin.jsx`, iterating arrays on every search or category change, as well as unrelated modal or typing changes.
**Action:** When working on top-level filterable dashboard/portfolio views, ensure derived lists from API calls (like `filteredProjects` or `filteredTrainings` based on a selected filter state) are wrapped in `useMemo`. This prevents redundant O(N) recalculations on all other state updates in the component.
